## 0. 一句话结论

1. **上一波「必须做」的升级已经落地并发布**：`3.5.11 → 3.6.0`，核心是 **Node.js 22+ 一等公民（CLI + 运行时）**，并顺带把依赖抬到 Node 兼容线（`view ^2.2.0`、`runtime-adapter ^1.2.2`、`server ^1.2.1` 等）。
2. **旧文档写的「依赖浪潮 0 / view 2.1」在数字上已经超额完成**（现已到 view **2.2.0**）；不要再按 2026-07-22 的缺口表去 bump 版本。
3. **下一波升级不再是「再抬 caret」**，而是旧《全面分析》里仍未兑现的 **产品/工程增强**：构建债（`csr-client-builder`）、生产安全默认、Streaming SSR、`dweb-cli test` 报告、Console（多应用）、Bun e2e 策略等。
4. **升级方法不变**：自底向上（L0 底座 → 子包 → dweb 编排）协同发版；`deno.json` 与 `package.json` **同号**；9-job CI 绿 → tag → `jsr publish`。

## 2. 框架定位（升级时不要偏离）

dweb 是 **编排层 / 产品线**，不是业务仓：

```text
CLI（init/dev/build/start/test/upgrade…）
  └─ core/App（生命周期 · 中间件 · 插件 · 配置）
       └─ feature/（router · render-* · build · load · ws/socket）
            └─ @dreamer/{server,router,render,view,esbuild,session,…}
                 └─ @dreamer/runtime-adapter（Deno | Bun | Node）
```

**刻意边界（旧文已冻结，升级仍遵守）：**

- 不做 Islands / 分区水合
- 不在 dweb 内再造测试执行引擎（`dweb-cli test` = launcher；用例用 `@dreamer/test`）
- 不把 auth/payment/queue 等业务包变成硬依赖
- 不重写 `App` 多模式矩阵

## 3. 上一波（3.5.11 → 3.6.0）当初怎么升、现在升完没有

### 3.1 计划来源

主执行文档：`.trae/documents/dweb-node-compat-plan.md`  
工程量预估文档曾建议「先别做完整 DX」；**实际立项做成了完整三端 CLI**，并以 **minor 3.6.0** 发布。

### 3.2 计划项 × 落地核对

| 计划项 | 状态 | 证据 |
| --- | --- | --- |
| `runtime.ts` 全导出加 `IS_NODE` | ✅ | `getRuntime`/`getSpawnArgsForDwebTask`/`getTestArgs`/`getRunArgs`… |
| `Deno.env.toObject` → `getEnvAll()` | ✅ | `getInheritedEnvForSpawn` |
| `getNodeRunArgsFromTaskString` + `DENO_ONLY_FLAGS` | ✅ | `deno run -A …` → `node --import tsx …` |
| `isMainModule` 替换 `import.meta.main` | ✅ | `src/utils/main-module.ts`；cli/setup 入口 |
| 错误文案 / locale 含 Node | ✅ | CHANGELOG 3.6.0 |
| 依赖同步到 Node 兼容线 | ✅ | ra ^1.2.2、view ^2.2.0、server ^1.2.1、render/router ^1.2.0… |
| `package.json`：去 private、`engines.node>=22`、tsx、`test:node` | ✅ | 现 version 3.6.0 |
| `test-node.mjs`（unit 子集） | ✅ | 51/64 unit（排除子进程类） |
| `test-node-e2e.mjs` + Playwright **1.59.1** 锁定 | ✅ | 超出原计划「Node 只跑 unit」——**加强了** |

### 3.3 相对「Node 工程量分析」的决策漂移（重要）

| 原建议 | 实际 |
| --- | --- |
| 默认不做 Node 一等公民；最多 prod MVP | **做了 CLI dev/build/start/test + e2e** |
| 估 14～24 人周完整一等公民 | 以「RA 已就绪 + dweb src 极少 Deno 直调」走通，成本低于原文悲观估 |
| Bun e2e 一并三端 | **Bun 浏览器 e2e 仍关**（Playwright 兼容性） |

→ 历史文档 **不要当「还没做 Node」的 TODO**；当「为何这样设计 / 哪些坑」的背景。

## 6. 标准升级操作手册（每次 bump 都走）

### 6.1 只升 dweb 编排（子包已发）

```text
1. 确认子包 JSR 已发布且 CI 绿
2. 改 dweb/deno.json + package.json 同号 caret（及 examples/init）
3. deno check / deno lint / deno test -A
4. bun test（unit）+ node test-node.mjs（+ 必要时 test-node-e2e）
5. 更新 docs/*/CHANGELOG + TEST_REPORT
6. 推 dev → 等 9 jobs 绿 → tag vX.Y.Z → jsr publish
7. 可选：验证 dweb-cli upgrade 能拉到新版
```

### 6.2 带子包能力的升级（如 Streaming）

```text
L0 runtime-adapter（若需）
  → L2/L3 server/router/render/view（先发）
  → L4 esbuild（若构建契约变）
  → L5 middlewares/plugins（若有）
  → dweb 抬下限 + 透传配置 + 示例 + 双/三端回归
```

顺序与《依赖分析》§6 一致；**禁止**只改 dweb caret、子包 imports 仍钉死旧底座。

### 6.3 版本号建议

| 变更类型 | 版本 |
| --- | --- |
| 文档/卫生/小修 | patch（3.6.x） |
| 新能力但兼容（流式可选、报告 CLI、builder 拆分） | minor（3.7.0…） |
| 配置/主入口 breaking | major（4.x）单独立项 |

Node 兼容已占用 **3.6.0 minor**；下一波产品增强适合 **3.7+**，不要无声塞进「再发一个 3.6.x 却大改行为」。

## 7. 成功标准（下一阶段「升级算完成」）

1. **无虚假版本缺口**：dweb 声明与 monorepo 已发布能力一致；image 等「声明未用」清掉或说清。  
2. **构建债可见改善**：builder 模块边界清晰 + golden 防回归。  
3. **生产路径可讲清**：PRODUCTION_CHECKLIST 与配置一致；安全能力 opt-in 但有官方配方。  
4. **测试真相**：CI 策略（含 Bun e2e）文档化；`dweb-cli test` 报告可被 CI 消费。  
5. **三端不回退**：Deno/Bun/Node 既有绿矩阵保持；新能力至少 Deno+Bun，Node 按风险加测。  
6. **不引入已否决方向**：Islands、自研 test 引擎、单应用 Console。
